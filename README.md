# Gamertab

Навчальний вебпроєкт для пошуку ігор, персональних рекомендацій і ведення власної ігрової бібліотеки.

Грицина Антон Олександрович, ТТП-32.

## Можливості

- Живий каталог ігор для різних платформ із пошуком, фільтром жанру та сторінками результатів.
- Повнотекстовий пошук збережених ігор за назвою, описом, жанрами, темами та режимами.
- Реєстрація з паролем або вхід через Google.
- Власна бібліотека зі статусами Planned, Playing, Completed, On hold і Dropped.
- Особисті оцінки, нотатки та дати проходження.
- Статистика бібліотеки за статусами, жанрами та місяцями завершення ігор.
- Власні колекції ігор із пошуком для додавання нових ігор.
- Завантаження власних обкладинок колекцій у Blob Storage.
- Автоматичне збереження описів ігор з IGDB після відкриття сторінки.
- Доступні оцінки IGDB, вікові рейтинги й орієнтовний час проходження.
- Платформи гри, ціна Steam у USD і доступна оцінка Metacritic для PC.
- Скриншоти з переглядом на весь розмір і відео на сторінці гри.
- Історія новин і оголошень Steam.
- Фонове оновлення новин відстежуваних ігор через чергу завдань.
- Персональні рекомендації на головній сторінці та популярні ігри для нових користувачів.

## Технології

C#, .NET 10, ASP.NET Core MVC, Razor, Bootstrap, PostgreSQL, Entity Framework Core та ASP.NET Core Identity. Для локального середовища використовується Docker Compose у WSL2.

Проєкт складається з одного застосунку Gamertab та одного проєкту Gamertab.Tests. У Controllers розташовані обробники сторінок і API, у Models моделі даних, у Data база та міграції, у Services інтеграції й рекомендації, у Views сторінки.

Для пошуку гри під час редагування складу колекції використовуються jQuery 4.0.0 і Select2 4.1.0. Підказки завантажуються із сервера після введення щонайменше трьох символів із затримкою 350 мс. Результати мають сторінки, а вже додані ігри приховуються. Гра імпортується з IGDB після підтвердження додавання. Якщо IGDB недоступний, форма показує повідомлення про недоступність пошуку. Файли бібліотек зберігаються в wwwroot/lib разом із ліцензіями.

Для повнотекстового пошуку використовується Lucene.NET 4.8.0-beta00018. Індекс зберігається в пам'яті, формується з PostgreSQL під час запуску та оновлюється після імпорту чи зміни гри. Окремий сервер для індексу не потрібен. Запит GET `/api/games?q=space%20dwarves` знаходить Deep Rock Galactic за описом. Збіги в назвах мають вищий пріоритет. Пошук враховує слова запиту без урахування регістру та підтримує початок останнього слова. Службові знаки не виконуються як синтаксис запиту. Такий самий пошук доступний в окремому режимі збереженого каталогу з параметром saved=true. Живий каталог отримує результати безпосередньо з IGDB.

Сторінка Statistics відкривається з My library. Графіки побудовано на Chart.js 4.6.1, який зберігається локально разом із ліцензією. Підрахунки виконуються на сервері лише для поточного користувача. Місячний графік охоплює останні 12 календарних місяців і враховує лише завершені ігри з датою завершення. Середня оцінка включає лише виставлені оцінки, зокрема нульові. Біля графіків можна розкрити ті самі дані в текстовому вигляді.

## Запуск

Потрібні .NET 10 SDK, PowerShell і Docker. На цьому комп'ютері Docker працює в Ubuntu-24.04 через WSL2.

```powershell
.\dev.ps1 run
```

Сервіс відкривається за адресою http://localhost:5180. Можна також відкрити Gamertab.slnx у Visual Studio, запустити базу й сховище через dev.ps1 up і вибрати профіль Gamertab.

Команда dev.ps1 run явно запускає локальне середовище Development. Ключі інтеграцій читаються з локального файлу .env у корені проєкту. Використовуються поля IGDB_CLIENT_ID, IGDB_CLIENT_SECRET, GOOGLE_CLIENT_ID та GOOGLE_CLIENT_SECRET. Цей самий файл підтримує Docker Compose, він виключений із Git. Якщо значень у .env немає, використовуються наявні User Secrets. Скрипт передає налаштування дочірньому процесу, а після завершення відновлює попередні змінні середовища. У консолі виводяться шлях до локальних налаштувань і стан Live discovery configured, без ключів.

```powershell
.\dev.ps1 test
.\dev.ps1 down
```

Тести використовують окрему базу SQLite в пам'яті та не змінюють бібліотеку у PostgreSQL. Команда down зупиняє контейнери, зберігаючи дані бази.

## Фонові оновлення новин

NewsUpdateWorker працює у фоні через ASP.NET Core BackgroundService. Раз на 15 хвилин він вибирає ігри, для яких хоча б один користувач увімкнув Follow news, та додає завдання в Azure Storage Queues. До одного пакета гра потрапляє лише один раз. Новий пакет створюється після завершення попереднього. Ігри без Steam App ID пропускаються.

Робітник отримує завдання, перевіряє, чи стежать за грою досі, завантажує оголошення Steam і зберігає нові записи. Повторна доставка не створює копій новин. Повідомлення видаляється після успішної обробки. Невдала обробка повторюється до трьох разів, після чого завдання переходить у чергу gamertab-news-failed. Некоректні повідомлення потрапляють туди одразу. Помилка черги або Steam записується в журнал і не зупиняє сайт.

Локально використовується Azurite 3.37.0 у Docker. Команда dev.ps1 run запускає PostgreSQL і Azurite, вмикає робітника та зберігає локальне підключення до черги в User Secrets. Обліковий запис Azure для цього не потрібен. Порт черги 10001 доступний лише на цьому комп'ютері. Повідомлення зберігаються в Docker volume після зупинки контейнерів.

Перша перевірка ігор з увімкненим Follow news виконується одразу після запуску застосунку. У консолі з'являються повідомлення Queued news updates і Processed news update. Новини доступні на сторінці гри. Під час роботи наступні перевірки відбуваються автоматично.

Налаштування NewsUpdates містяться в appsettings.json. ScanIntervalMinutes задає інтервал планування, PollIntervalSeconds інтервал очікування нових повідомлень, RetryDelaySeconds затримку повторної обробки. Для підключення справжнього Azure Storage потрібно змінити ConnectionStrings:QueueStorage та ввімкнути NewsUpdates:Enabled у конфігурації середовища. Без налаштування черги залишається доступне отримання новин під час відкриття сторінки гри.

## Обкладинки колекцій

У формі створення або редагування колекції є один блок обкладинки. Можна вибрати HTTPS-посилання, файл PNG/JPEG до 2 МБ або відсутність обкладинки. Назва, опис і вибрана обкладинка зберігаються однією кнопкою. Для наявного файлу порожнє поле завантаження означає збереження поточного зображення. Перехід на посилання або вибір No cover видаляє попередній завантажений файл.

Сервер перевіряє розмір і сигнатуру файлу та генерує власне ім'я. JSON API також підтримує окремі операції з обкладинкою.

Зображення зберігаються у приватному контейнері Azure Blob Storage. Застосунок перевіряє власника колекції перед читанням і зміною файлу. Ключі сховища не передаються браузеру. Заміна обкладинки та видалення колекції також видаляють попередній файл. Помилки очищення сховища записуються в журнал.

Локально Blob Storage працює в тому самому Azurite, що й черги. Команди dev.ps1 up і run запускають обидва сервіси. Порт Blob Storage 10000 доступний лише на цьому комп'ютері. Дані зберігаються в Docker volume. За замовчуванням використовується ConnectionStrings:QueueStorage. Окреме підключення можна задати через ConnectionStrings:BlobStorage, а назву контейнера через BlobStorage:ContainerName. Без підключення сховища залишається доступне зовнішнє посилання на обкладинку.

## Доступ до IGDB

IGDB використовує доступ через зареєстрований Twitch-застосунок. Для запуску через dev.ps1 ключі можна задати в локальному .env як IGDB_CLIENT_ID та IGDB_CLIENT_SECRET. Скрипт також переносить їх у .NET User Secrets для запуску через Visual Studio. Секретні налаштування виключені з Git.

У Visual Studio можна вибрати Manage User Secrets для проєкту Gamertab. У VS Code можна відкрити файл `%APPDATA%\Microsoft\UserSecrets\<UserSecretsId>\secrets.json`, де UserSecretsId вказаний у Gamertab.csproj. Потрібні поля Igdb:ClientId та Igdb:ClientSecret. Паролі й ключі в Git не додаються.

Для новин конкретної гри використовується Steam News API. Імпорт бібліотеки Steam буде окремою можливістю. Бібліотека облікового запису відрізняється від переліку ігор, установлених на певному ПК.

Пошук на головній сторінці й у формі додавання до колекції звертається до IGDB та не обмежений іграми в локальній базі. Пошук охоплює різні платформи. Без пошукового запиту доступні популярні ігри за кількістю оцінок. Модифікації, комплекти та дублікати спеціальних видань відфільтровуються. Відкрити опис гри можна без акаунта. До локальної бази потрапляють лише відкриті або додані до колекції ігри. Якщо точного збігу на сторінці немає, інші результати IGDB показуються з поясненням. Якщо служба недоступна чи не налаштована, показується помилка з кнопкою повтору, без підміни результатів локальними іграми. За бажанням можна окремо перейти до пошуку збережених ігор через Search saved games або параметр saved=true.

Для користувача з бібліотекою головна сторінка спочатку показує персональні рекомендації. Їх основою є високо оцінені, поточні та пройдені ігри. Низько оцінені й покинуті ігри не використовуються як уподобання. Кандидати надходять із переліків схожих ігор IGDB та окремого пошуку за жанрами, темами й перспективою гри. Збіг лише за режимом Single player недостатній. Загальні позначки Adventure, Indie та Action мають меншу вагу. Уже додані до бібліотеки ігри виключаються, а кожна рекомендація має пояснення. Перспектива використовується під час живого підбору й окремо не зберігається в базі.

## Вхід через Google

У Google Cloud Console потрібно створити проєкт, налаштувати Google Auth Platform і додати OAuth-клієнт типу Web application. Для локального запуску його Authorized redirect URI має бути `http://localhost:5180/signin-google`.

У .NET User Secrets потрібні поля `Authentication:Google:ClientId` та `Authentication:Google:ClientSecret`. Після їх додавання застосунок потрібно перезапустити. Для запуску всього сервісу через Docker Compose ці значення передаються через змінні `GOOGLE_CLIENT_ID` та `GOOGLE_CLIENT_SECRET`.

Новий користувач отримує акаунт після підтвердженого входу в Google. Для наявного акаунта з паролем потрібно спочатку ввійти звичайним способом, відкрити Account і натиснути Connect Google. Збіг адреси пошти не підключає Google автоматично. Після підключення обидва способи входу відкривають ту саму бібліотеку.

У режимі Testing користувачів для перевірки потрібно додавати в Audience у Google Auth Platform. Якщо клієнт Google не налаштований, залишається доступний вхід із паролем. Gamertab запитує лише основні дані профілю та адресу пошти, без доступу до Gmail або Google Drive.

## Дані про ігри

Сторінка гри містить опис, рейтинги, медіа, ціну, час проходження та новини в одному місці. Компактна панель переходів залишається зверху під час прокручування. Feedback відкриває сторінку звернень у GitHub.

Скриншоти й ідентифікатори відео завантажуються з IGDB окремим запитом із кешуванням на 10 хвилин. Показується до шести різних скриншотів. У переглядачі працюють кнопки перемикання, стрілки клавіатури й Escape. Для відео спочатку вибирається трейлер, якщо він доступний. Плеєр YouTube завантажується лише після натискання Play, також є пряме посилання на відео. Відсутність медіа не створює порожніх блоків, а помилка джерела не заважає переглядати іншу інформацію про гру. База даних і файли відео для цієї можливості не збільшуються.

Біля зовнішніх даних зазначається джерело. Оцінка критиків IGDB не є оцінкою Metacritic. Оцінка Metacritic для PC показується окремо лише тоді, коли її надає картка Steam. За наявності додається пряме посилання на Metacritic. Для ігор без такої оцінки блок прихований. Це не гарантує покриття всіх ігор, оцінених на самому Metacritic.

Ціна, знижка та безкоштовний доступ беруться з публічного endpoint Steam Store appdetails для магазину США. Відповідь кешується на 10 хвилин. Показуються лише ціни, які джерело позначило як USD. Біля ціни є час отримання та уточнення про регіон. Відсутня ціна не замінюється нулем. Цей endpoint відрізняється від документованого Steam Web API й може змінитися. Його недоступність не блокує опис гри. Для ігор без зв'язку зі Steam ціна не вигадується. Платформи надходять з IGDB незалежно від наявності в Steam.

IGDB може надавати час до титрів, час із частиною додаткових завдань і час на проходження на 100%. Наявність цих значень залежить від гри. Повне проходження не означає автоматичне включення всіх DLC. Відсутні значення не замінюються нулем.

Невеликий початковий каталог дозволяє відкрити сервіс до підключення API. Його описи підготовлено для початку роботи, а неперевірені оцінки та час проходження залишено порожніми.

## Подальша робота

1. Розширити перевірки каталогу, бібліотеки та колекцій для нових можливостей.
2. Додати імпорт бібліотеки Steam.
3. Покращити рекомендації з урахуванням реакцій користувача.
4. Розширити фільтри каталогу.
5. Додати імпорт і експорт бібліотеки.
6. Підготувати автоматичне розгортання й MCP-сервер.

Мета проєкту полягає в послідовному вивченні веброзробки на робочому сервісі. Нові можливості додаються після перевірки попередніх.

## Перевірки

Браузерні тести написані на C# із Playwright. Вони запускають окремий Kestrel на випадковому порту, використовують тимчасову SQLite у пам'яті та контрольовані відповіді IGDB і Steam. Основна база й особисті акаунти не змінюються. Потрібен встановлений Microsoft Edge. Можна вибрати встановлений Chrome через змінну GAMERTAB_TEST_BROWSER зі значенням chrome. Завантажувати окремий браузер не потрібно, сам браузер працює у фоновому режимі.

```powershell
.\dev.ps1 browser-test
```

П'ять сценаріїв перевіряють реєстрацію та вхід, пошук і збереження прогресу, роботу Select2 і колекцій, ізоляцію акаунтів, галерею й відкладене завантаження трейлера, графіки та відображення статистики на вузькому екрані. Зовнішні картинки й відео в тестах замінено контрольованими відповідями, тому їх доступність не впливає на результат. Справжній вхід у Google не автоматизується цими сценаріями.

Команда також вимірює покриття рядків і гілок .NET через Coverlet, показує відсотки та зберігає coverage.cobertura.xml у `.local\browser-tests`. Це покриття серверного коду браузерними сценаріями, включно з міграціями, а не відсоток перевірених можливостей або покриття JavaScript. Звичайні перевірки без браузера запускаються через `.\dev.ps1 test`. Обидві команди використовують окрему папку збірки й можуть працювати паралельно з відкритим сайтом.

Перевіряємо доступ до власних записів, правильність дат і оцінок, повторне додавання ігор, пагінацію та захист операцій зміни даних. Звичайні автоматичні тести мають працювати без ключів зовнішніх служб. Живі інтеграції перевіряються окремо.

У Gamertab.Tests є автоматичні перевірки основних можливостей. Перевірки Google проходять через справжній обробник OAuth із контрольованими відповідями зовнішньої служби. Вони перевіряють створення та підключення акаунтів, відмову від входу, захист state і cookie, небезпечні адреси повернення та збереження бібліотеки. Пошук перевіряється з контрольованими відповідями IGDB. Для вибору гри в колекцію перевіряються мінімальна довжина запиту, сторінки, імпорт після підтвердження, дублікати, робота без IGDB та доступ лише власника. Окремі перевірки кешу підтверджують повторне використання відповідей, розділення пошуку та сторінок і очищення після зміни гри. Повнотекстовий пошук перевіряється за описами й темами, для початку слова, ранжування, сторінок, великих зміщень та оновлення індексу після імпорту. Реальний вхід через Google та живі дані перевіряються окремо.

Для черг є ще 4 інтеграційні тести з реальним Azurite та окремими тимчасовими чергами. Вони перевіряють фонову обробку без відкриття сторінок, повторну доставку, вимкнення Follow news, повторні спроби й чергу помилок. Відповіді Steam у цих тестах контрольовані. Запуск виконується окремо.

```powershell
.\dev.ps1 queue-test
```

Без цієї команди тести черг пропускаються, щоб звичайні перевірки могли працювати без Docker. Тестові черги видаляються після завершення перевірок.

Окрема перевірка обкладинок використовує справжній локальний Blob Storage. Вона перевіряє завантаження, заміну й видалення файлів, обмеження доступу та відхилення неправильних і завеликих файлів. Також перевіряється збереження бібліотеки після видалення колекції.

```powershell
.\dev.ps1 blob-test
```

Для цих перевірок створюються окремі тимчасові контейнери, які видаляються після завершення. Без цієї команди тести Blob Storage пропускаються. Власні колекції користувача не змінюються.

У папці api-tests міститься колекція Gamertab.postman_collection.json із 40 запитами та 65 перевірками. Вона перевіряє каталог, реєстрацію, вхід і вихід, операції з бібліотекою та колекціями, дублікати, неправильні дати й оцінки, захист CSRF і доступ без входу. Окремі запити перевіряють повнотекстовий пошук за описом і тематикою.

Для запуску потрібен [Postman CLI](https://learning.postman.com/docs/postman-cli/postman-cli-installation/). Скрипт знаходить його через PATH або за локальним шляхом `.local\tools\postman\postman-cli.exe`. На цьому комп'ютері використовується локальний варіант на диску Q.

```powershell
.\dev.ps1 api-test
```

Команда створює тимчасову базу PostgreSQL, застосовує міграції, запускає окремий екземпляр Gamertab і виконує колекцію без ключів зовнішніх служб. Після завершення вона зупиняє тестовий сервер і видаляє тимчасову базу разом із тестовим акаунтом. Основна база залишається без змін. Результат зберігається у файлі results.txt в окремій папці `.local\postman`. Вхід у Postman для локального запуску не потрібен. Повідомлення CLI про авторизацію стосуються публікації результатів у хмарі.

Колекцію можна також імпортувати в Postman і запустити вручну. Змінна baseUrl за замовчуванням містить `http://localhost:5180`. Такий запуск створює тестовий акаунт у вибраній базі й видаляє створені ним записи бібліотеки та колекцій.

## Кешування API

Відповіді GET `/api/games` і `/api/games/{id}` для відвідувачів без входу зберігаються в пам'яті сервера на 60 секунд через ASP.NET Core Output Cache. Пошуковий запит, розмір сторінки, її зміщення та адреса гри враховуються окремо. Після імпорту або оновлення гри кеш каталогу очищається.

Запити користувачів після входу обходять спільний кеш. Особисті бібліотеки, колекції та дані сесії в нього не потрапляють. Відповіді з помилками також не зберігаються. Кеш зовнішніх запитів IGDB і Steam працює окремо.
